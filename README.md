# Grelqa

Движок анонимных литературных конкурсов на Next.js App Router, React и TypeScript. Публичные страницы читают локальную SQLite через Drizzle ORM. Литературное оформление, мобильные стили и системные шрифты сохранены.

## Установка и запуск

Node.js **26.13.0** указан в `.nvmrc`. Совместимость проверена: Next.js 16.4.3 требует Node >=20.9; ESLint 10.14.0 — ^20.19, ^22.13 или >=24; TypeScript 5.9.3 — >=14.17; tsx 4.23.15 — >=18. Drizzle ORM 0.45.4 поддерживает `@libsql/client` >=0.10, используется 0.18.0; Drizzle Kit — 0.31.11. Драйвер работает с локальным SQLite, облачный аккаунт не нужен.

В `overrides` адресно обновлён вложенный esbuild у `@esbuild-kit/core-utils` до 0.25.12: это устраняет известную уязвимость зависимости Drizzle Kit. Генерация миграций с ним проверена. Существующий ESLint 10 сохранён; npm предупреждает о диапазонах peer-зависимостей некоторых плагинов Next.js, но установка, линтер и сборка проходят.

```bash
nvm install
nvm use
npm ci
# Только при первом запуске, если своего .env ещё нет:
cp .env.example .env
# В .env задайте SESSION_SECRET (команда генерации ниже), APP_URL и MAIL_MODE.
npm run db:migrate
npm run db:seed
npm run dev
```

Откройте http://localhost:3000. Если nvm отсутствует, установите указанную версию Node другим способом. Существующий `.env` не перезаписывайте: добавьте в него `DATABASE_URL=file:./data/grelqa.db`. Путь относительно корня проекта; разрешены только локальные `file:` URL.

`db:migrate` создаёт каталог и файл базы, применяет только ещё не выполненные миграции. `db:seed` необязателен: без него список конкурсов пуст. Приложение не применяет миграции и не запускает seed автоматически. Сборка не требует существующей базы; для запуска страниц нужна мигрированная база.

## Проверки и производственный режим

```bash
npm run check
npm run test:db
npm run build
npm run test:pages
npm run test:auth
# npm start требует production-настройки HTTPS и SMTP.
npm start
```

- `check` — ESLint и TypeScript; отдельно: `npm run lint`, `npm run typecheck`.
- `test:db` — новая временная база в `/tmp`: повторные миграции и seed, сохранность пользовательских записей, уникальность, внешние ключи, ограничения, история туров и фильтрация секретных данных.
- `test:pages` — требует готовую сборку; создаёт другую временную базу и временный локальный сервер на свободном порту. Проверяет HTML и RSC-ответы главной, конкурсов и рассказов, чтение изменённого в SQLite названия, списки групп, пустое состояние, экранирование HTML, форматирование и отсутствие секретной темы, условий и данных авторства. Проверяет неизвестные ссылки и запрет прямого открытия скрытых работ и работ на закрытых этапах. Затем закрывает сервер и удаляет только собственный временный каталог.
- `build` — производственная сборка; `start` запускает её с настройками из `.env`.

Тесты сами задают `DATABASE_URL`, не используют рабочую базу и не сбрасывают её.

## Модель хранения

Схема: `src/db/schema.ts`; SQL-миграции и снимки: `drizzle/`. Типы выводятся из Drizzle-схемы, дополнительные классы моделей не используются.

| Таблица | Назначение и связи |
| --- | --- |
| `users` | Уникальный email, хеш пароля, дата подтверждения email. Публичное имя пока не определено. |
| `contests` | Организатор → User, slug, описание, ссылка обсуждения, ограничения длины и вместимости, точные даты, этап и причина несостоявшегося конкурса. |
| `contest_themes` | Одна тема и массив дополнительных условий на конкурс; моменты ввода/публикации, необязательные поля одноразового доступа. |
| `participations` | Одно участие User в Contest; назначенная группа первого тура, флаг финалиста и обязанности голосовать по турам. |
| `contest_groups` | Группы с номером, туром и вместимостью; уникальный номер внутри конкурса и тура. |
| `stories` | Название, автор через Participation, структурированный Unicode-текст с абзацами, курсивом и полужирным; даты, статус, длина и версия алгоритма подсчёта. |
| `story_rounds` | Рассказ в группе конкретного тура, снятие с датой/причиной и необязательные итоговые очки/место. Снятие в финале не меняет первый тур. |
| `ballots` | Один бюллетень Participation за тур, группа, даты создания/обновления/отправки. |
| `ballot_entries` | Рассказ и место 1–6; рассказ и место не повторяются в одном бюллетене. Очки не дублируются. |

Все соединения включают `PRAGMA foreign_keys=ON`. Составные внешние ключи не позволяют связывать участие, рассказ, группу и бюллетень из разных конкурсов/туров; позиция бюллетеня ссылается на рассказ в той же группе. Удаление связанных записей ограничено (`RESTRICT`); снятие сохраняет рассказ, бюллетени и позиции. Места в `story_rounds` не уникальны: разделённые места допустимы. Даты хранятся как Unix-миллисекунды, отображаются в МСК. Начало приёма в 15:00 МСК и не более одного старта в день проверяются ограничениями SQLite. Нулевой минимум/максимум означает отсутствие соответствующего ограничения длины.

Пока не определён конкурсный алгоритм подсчёта Unicode-знаков, `length` и `lengthAlgorithm` допускают `NULL`. Seed не вводит собственный алгоритм и не выдает короткие тексты-примеры за результат настоящей модерации. Формат структурированного текста и поля публикации — технический выбор этого шага, не новое конкурсное правило.

## Публичные данные и демонстрационные записи

`/` и `/contests/[slug]` читают данные при каждом запросе, без статической копии базы в сборке. `src/db/index.ts` и `src/db/public-contests.ts` защищены `server-only`. Публичные запросы перечисляют разрешённые поля, не читают пользователей, авторство рассказов и бюллетени. Тема и условия присоединяются в SQL только при наступивших начале приёма и `publishedAt`, и вне этапа подготовки. Авторство сейчас вообще не выдаётся; будущая публикация должна учитывать конец голосования всего конкурса, включая финал. Признак `completed` сам по себе не является разрешением раскрытия авторов.

Seed находится в `scripts/seed.ts` и `scripts/demo-contests.ts`: три вымышленных пользователя с неизвестными случайными паролями (хеши scrypt), три конкурса, одна группа, три участия, три рассказа с форматированием (один развёрнутый, два коротких), три бюллетеня и шесть позиций. У будущего конкурса есть настоящая скрытая демотема для проверки непубликации. Даты, ограничения и вручную заданные этапы — параметры примеров.

Seed выполняется транзакцией и только добавляет записи с устойчивыми `demo-*` ID. Он не обновляет существующие записи, не удаляет данные и не сбрасывает базу. Совпадение уникального email/slug с другой записью вызывает ошибку и откат транзакции; это намеренно, чтобы не менять чужие данные. После ручных изменений, конфликтующих с демосвязями, seed также может остановиться вместо перезаписи. Команды сброса базы нет.

## Публичное чтение рассказов

Команды запуска не изменились. В уже заполненной `data/grelqa.db` есть три рассказа: причина их прежнего отсутствия в интерфейсе — отсутствие запросов и компонентов чтения. Повторный seed для такой базы не нужен. Для новой базы выполните `npm run db:migrate` и `npm run db:seed`, как описано выше.

Адреса для проверки:

- `/contests/city-between-lines#stories` — список трёх рассказов в группе первого тура.
- `/contests/city-between-lines/stories/demo-city-story-1` — «Переулок забытых часов».
- `/contests/city-between-lines/stories/demo-city-story-2` — «Окно на восьмом этаже».
- `/contests/city-between-lines/stories/demo-city-story-3` — «Последний трамвай».
- `/contests/letters-to-november#stories` — пустое состояние.
- `/contests/city-between-lines/stories/unknown` — страница «не найдено».

`src/db/public-stories.ts` защищён `server-only`. Один серверный фильтр применяется к списку, странице чтения и её метаданным: статус `admitted`, наступивший `stories.publishedAt`, отсутствие снятия и начавшийся первый тур; этап — первый тур, второй тур либо завершение. Авторство вообще не запрашивается и пока не выводится даже после завершения конкурса. Скрытый рассказ не раскрывается ни через название страницы, ни через HTML/RSC.

Точный момент первой публикации и доступность снятых работ или работ несостоявшегося конкурса в ТЗ ещё открыты. До их согласования применено осторожное техническое ограничение: не показывать рассказы во время подготовки, приёма, модерации и несостоявшегося конкурса; не выдавать снятые работы. Это временная политика чтения, а не утверждение новых правил. Наличие `publishedAt` само по себе не публикует черновик и не меняет этап автоматически.

Список группирует рассказы только по опубликованным группам. Для финалиста используется последняя опубликованная группа доступного тура, остальные работы остаются в группах первого тура; дубликатов рассказов нет. Если опубликованной группы нет, работа показана отдельно, без раскрытия неопубликованного распределения.

`src/lib/story-content.ts` проверяет структуру текста, `src/components/story-text.tsx` выводит только абзацы, текст, `<em>` и `<strong>`. Чужие атрибуты не передаются; `dangerouslySetInnerHTML` не используется. HTML/скрипты в тексте экранируются React. Ширина чтения ограничена, длинные слова переносятся, оформление адаптировано для телефона.

Если сохранённая конкурсная длина отсутствует (`NULL`), интерфейс показывает справочное `≈ N знаков с пробелами`: число Unicode-кодовых точек текстовых фрагментов, между абзацами — два перевода строки; заголовок и разметка не учитываются. Этот объём не записывается в базу, не используется для допуска, групп или результатов и не утверждает пока не согласованный конкурсный алгоритм подсчёта.

## Аутентификация

Добавлены `/register`, `/login`, `/registration-status`, `/confirm-email`, `/forgot-password`, `/reset-password` и `/account`. Состояние входа и выход доступны в шапке. Кабинет проверяет сессию и подтверждение email на сервере. Неподтверждённая сессия допускает только состояние регистрации, повторную отправку и выход; публичное чтение остаётся доступно всем, как и без регистрации. Подача рассказов и участие пока не реализованы.

Новые зависимости: iron-session 9.0.1 (Node >=22.13), @node-rs/argon2 2.2.2 (Node >=10), Nodemailer 10.3.1 (Node >=20), Zod 4.6.7. Они проверены на Node 26.13.0. Пароли новых пользователей хешируются Argon2id (19 MiB, 2 прохода, 1 поток), старые seed-хеши scrypt сохранены. Пароль — от 12 до 128 символов, без обрезания пробелов. Email обрезается по краям и приводится к нижнему регистру и при регистрации, и при входе/восстановлении; принимается ASCII-email, без специальных правил Gmail/удаления точек/плюсов. Новый уникальный индекс `lower(trim(email))` защищает от гонок. Существующие email не переписываются. Если в старой базе уже есть конфликтующие варианты email, миграция остановится: сначала нужно вручную разрешить конфликт, данные не удаляются.

Миграция `0001_flippant_nemesis.sql` только добавляет индекс и три таблицы: `auth_sessions`, `auth_tokens`, `auth_rate_limits`. Старые миграции, конкурсы и тексты не изменяются. `db:seed` не создаёт известных паролей для демопользователей; зарегистрируйте отдельную учётную запись.

### Локальная проверка писем

1. Выполните `nvm use`, `npm ci`, `npm run db:migrate`. В существующий `.env` добавьте недостающие поля из `.env.example`, не перезаписывая DATABASE_URL.
2. Создайте SESSION_SECRET командой ниже и сохраните результат в `.env`. Не публикуйте секрет. Укажите `APP_URL=http://localhost:3000`, `MAIL_MODE=local`, `MAIL_DIRECTORY=.local/mail`.
3. Запустите `npm run dev` и откройте `/register`. Введите email и дважды пароль. До подтверждения `/account` переводит на `/registration-status`.
4. В терминале появится только путь к JSON-письму в `.local/mail`. Откройте файл в редакторе и скопируйте полную ссылку, включая `#token=…`, в адресную строку браузера. Нажмите «Подтвердить email». Простое открытие ссылки ничего не меняет — почтовые сканеры не расходуют её.
5. Перейдите в кабинет; обновите страницу. Выполните выход и снова войдите. Для проверки повторной отправки используйте неподтверждённую учётную запись и кнопку на странице состояния регистрации.
6. На `/forgot-password` запросите письмо. Откройте новую ссылку из файла, введите новый пароль дважды. Старые сессии на всех устройствах должны потерять доступ; старый пароль больше не подходит. Повторная ссылка сообщает об использовании; просроченная — об истечении срока. Подтверждение действует 24 часа, сброс — 30 минут.

```bash
node -e "console.log(require('node:crypto').randomBytes(48).toString('base64url'))"
```

Локальные письма содержат секретные ссылки, сохраняются с правами 0600, каталог создаётся с 0700. Внутри проекта разрешён только игнорируемый `.local/`, либо можно указать отдельный каталог вне проекта. Письма никогда не размещаются в `public`. Папка `.local/` исключена из Git. В обычных логах нет паролей и токенов; fragment ссылки не уходит в HTTP/access-логи. Не переносите токен в query string. Формы требуют JavaScript.

### SMTP и production

В production задайте `APP_URL=https://ваш-домен`, случайный `SESSION_SECRET`, `MAIL_MODE=smtp`, `MAIL_FROM`, `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE` и при необходимости пару `SMTP_USER`/`SMTP_PASSWORD`. `SMTP_SECURE=true` обычно используется с портом 465; для 587 — false и STARTTLS. В production STARTTLS обязателен, если не включён implicit TLS; проверка сертификата не отключается. Ссылки строятся только от APP_URL, а не от Host/X-Forwarded-Host запроса. SMTP-секреты не попадают в браузер и логи.

Локальная почта допускается **только** в development (`npm run dev`). `npm start` с MAIL_MODE=local либо неполной почтовой конфигурацией завершится явной ошибкой конфигурации. Перед `npm start` настройте SMTP и HTTPS. Сборка не отправляет письма и не требует рабочей базы. Для проверки реальной доставки, TLS и попадания в почтовый ящик необходим настроенный SMTP-сервис — эти действия выполняются вручную.

### Сессии и защита

В cookie находится только защищённый iron-session случайный идентификатор; SQLite хранит его SHA-256-хеш. Срок сессии — 30 дней без автоматического продления. Cookie — HttpOnly, SameSite=Lax, Path=/; в production Secure и префикс `__Host-`, без Domain. Каждый запрос кабинета проверяет существование и срок сессии в базе; браузерный кеш cookie не заменяет отзыв на сервере. Новый вход меняет идентификатор текущей сессии, выход удаляет её, сброс пароля удаляет все сессии пользователя.

Токены из 32 случайных байт хранятся только как SHA-256 с разделением назначения (`verify`/`reset`). Расходование по `usedAt`/`expiresAt`, изменение пользователя и отзыв сессий выполняются одной транзакцией; использованные записи остаются для понятного сообщения о повторе. Сброс также отзывает остальные ссылки сброса. Пароль никогда не извлекается и не отправляется.

Все изменения — POST `/api/account/[action]`, с обязательной точной проверкой Origin против APP_URL и запретом Sec-Fetch-Site=cross-site. CORS не разрешён. GET не меняет состояние. Формы ограничены 8 KiB, валидируются Zod на сервере, ошибки не возвращают SQL/SMTP-исключения. Регистрация проверяет повтор пароля и уникальность email; восстановление возвращает одинаковое сообщение при неизвестном email, лимите для адреса и ошибке доставки. Поиск адреса и отправка восстановления выполняются через Next.js after после ответа, чтобы длительность SMTP не выдавала существование аккаунта. Это не долговечная очередь: если процесс оборвётся до отправки, запросите письмо повторно.

Счётчики SQLite сохраняются при перезапуске: вход — 5 попыток на адрес за 15 минут; регистрация — 3 на адрес в час; письма — 3 на пользователя и назначение в час; запрос восстановления — 3 на адрес в час. Дополнительно общий лимит: 100 входов или 30 запросов каждого другого действия за 15 минут (кроме выхода). Это сознательные начальные настройки для одного локального сервера; в большом развёртывании потребуется настроить лимиты под нагрузку. Подставляемому X-Forwarded-For приложение не доверяет. Никакой глобальный лимит не блокирует выход.

`npm run test:auth` после build автоматически проверяет HTTP-регистрацию, нормализацию/уникальность, повтор пароля, ограниченную сессию, production-атрибуты cookie, CSRF, конкурентное расходование, истечение и повтор токенов, вход/выход, сохранение и истечение сессий, отзыв после сброса, отказ старому паролю, доступ к кабинету и лимиты. Проверяет сохранение писем в development и запрет local/неполного SMTP в production. Используются только отдельная временная SQLite и каталог писем. Production HTTP-сервер теста обращается к закрытому локальному SMTP-порту; успешную файловую доставку проверяет сервис в development. Реальная доставка SMTP и клики в браузере проверяются вручную по шагам выше.

Документация: [iron-session](https://github.com/vvo/iron-session), [Nodemailer SMTP](https://nodemailer.com/smtp/).

Рабочая база и её journal/WAL/SHM исключены из Git; схема, миграции, снимки и seed сохраняются. Не меняйте уже применённые миграции. Перед изменениями рабочей базы сохраняйте резервную копию.

Пока не реализованы подача рассказов, приём бюллетеней, распределение, подсчёт итогов и автоматические переходы. При будущих операциях записи сервер должен проверять запрет голосования за себя, право голосовать и финалиста, назначенную группу, этап и дедлайн, допустимость произведения и полноту бюллетеня. Это нельзя заменить одними FK/UNIQUE. При закрытии тура сначала снимаются работы непроголосовавших, затем считаются результаты; очки снятых работ теряются без сдвига остальных позиций. Сейчас таких операций нет.

Открыты: точный подсчёт длины; правила публичного имени; равенства, квоты и распределение; действительность бюллетеня при изменении работ; момент первой публикации; раскрытие снятых работ и несостоявшегося конкурса; завершение с одной группой; остальные вопросы из [документа требований](docs/grelqa_rules_and_spec.md). Предложения в документе не становятся правилами автоматически. SQLite и миграции согласованы текущим запросом. PostgreSQL сейчас не реализуется.

Документация: [Drizzle + SQLite](https://orm.drizzle.team/docs/get-started/sqlite-new), [Next.js](https://nextjs.org/docs/app/getting-started/installation).
