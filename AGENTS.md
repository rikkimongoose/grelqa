# Работа с Grelqa

## Требования и границы

Сначала прочитайте `docs/grelqa_rules_and_spec.md`. Различайте принятые решения, исходные правила, предложения и нерешённые вопросы. Предложения не являются согласованными требованиями. Не изменяйте документ требований без запроса пользователя.

Текущий шаг — публичный демонстрационный каркас. Аутентификация, SQLite, голосование и автоматическая смена этапов отложены. Не создавайте фиктивно работающие формы. Сохраняйте существующие документы и настройки Git; коммиты, push и развёртывание требуют отдельного запроса.

## Устройство

- `src/app/layout.tsx` — общий каркас, навигация, метаданные и язык.
- `src/app/page.tsx` — список конкурсов.
- `src/app/contests/[slug]/page.tsx` — страница конкурса, статические параметры и 404 для неизвестного slug.
- `src/app/not-found.tsx` — страница 404.
- `src/app/globals.css` — оформление и мобильные стили.
- `src/components/stage-badge.tsx` — метка этапа.
- `src/lib/contests.ts` — типизированные вымышленные публичные данные и форматирование дат в МСК. Этапы заданы вручную; секретные темы здесь хранить нельзя.

Используются серверные компоненты App Router, TypeScript strict и обычный CSS. Нет базы, API, секретов и внешних шрифтов. Не раскрывайте авторство до окончания голосования по всему конкурсу и тему до старта.

## Команды

Node.js указан в `.nvmrc`. Установка: `nvm use`, затем `npm ci`.

- `npm run dev` — локальная разработка.
- `npm run lint` — ESLint.
- `npm run typecheck` — TypeScript без генерации JS.
- `npm run check` — обе проверки.
- `npm run build` — производственная сборка; запускать перед сдачей изменений.
- `npm start` — запуск готовой сборки.

Проверяйте главную, все демонстрационные конкурсы, неизвестный slug (404), мобильный вид и навигацию с клавиатуры. Lock-файл обновляйте вместе с зависимостями. Документация установленного Next.js находится в `node_modules/next/dist/docs/`, если поставляется с выбранной версией; официальная документация: https://nextjs.org/docs.
