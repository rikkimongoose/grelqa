# Уточнения правил группировки от 31 октября 2026 года

Дополнение к `grelqa_rules_and_spec.md` версии 0.4. Решения согласованы пользователем в ответах на вопросы при реализации первого тура. Исходный документ сохранён; перечисленные ниже решения закрывают соответствующие открытые вопросы, остальные предложения не становятся правилами автоматически.

## Распределение

Учитываются допущенные, не снятые работы. Пусть N — их число, C — исходная вместимость группы, F — допустимое число финалистов. Эффективная вместимость E = max(C, ceil(N / F)), число групп G = ceil(N / E). Увеличение минимально необходимое; исходная настройка C сохраняется, фактическое E фиксируется в результате и группах.

Рассказы сортируются от коротких к длинным и распределяются последовательными сбалансированными блоками. Размер базового блока q = floor(N / G), остаток r = N mod G; первые r групп получают q+1 работу, остальные — q. Например, 10 рассказов при эффективной вместимости 4 дают 4/3/3, а не 4/4/2. Циклическая раздача не используется.

Для стабильного порядка равных длин используется дата добавления по возрастанию, затем название по возрастанию и стабильный ID. Названия сравниваются стандартным `Intl.Collator("ru", { usage: "sort", sensitivity: "variant", numeric: false })`; ID — лексикографически. Это технический порядок формирования, не способ определения призовых мест.

## Назначение группы

Выбирается самый длинный рассказ автора; при равенстве — более ранний по точной дате добавления, затем название от А до Я. При полном совпадении используется стабильный ID только для выбора группы. Назначение и ID выбранного рассказа фиксируются; снятие или повторный запуск не меняют их автоматически. Запрет голосовать за любую свою работу сохраняется.

Формирование требует заполненных сопоставимых длин одной версии. Конкретный окончательный Unicode-подсчёт остаётся открытым; существующее временное соглашение прототипа и его версия не изменены. Длины старых записей автоматически не пересчитываются.

## Несостоявшийся конкурс

При явном запуске операции после завершения приёма и модерации проверяются допущенные работы. Отсутствие таких работ, одна работа, все работы одного автора или отсутствие своевременно введённой темы дают исход failed с сохранением причин и истории. Незавершённая модерация (`submitted`) не считается готовым набором для этой проверки.

Ввод темы допустим в момент старта: enteredAt <= submissionsStartAt. Пустая или пробельная тема остаётся отдельным открытым вопросом; если только от него зависит результат, операция останавливается для уточнения.

Результат проверки failed сохраняется атомарно и повторно возвращается без пересчёта. Это не разрешает автоматически переписывать уже начавшиеся туры или повторять проверку после снятия непроголосовавших: дальнейшие моменты проверки пока не определены.

## Совместимость и границы

Новые распределения имеют версию `size-blocks-v2`, новые отрицательные результаты проверки — `admitted-viability-v1`. Сохранённые `unambiguous-single-group-v1` возвращаются без изменений; переигрывать их под новые правила нельзя.

Момент публикации рассказов, запуск голосования, бюллетени, подсчёт баллов, призовые равенства и выход в финал этим решением не определяются и не реализуются.

Позднейшее уточнение того же дня: момент публикации определён отдельно в [решениях о видимости](submission_visibility_decisions.md). Успешное формирование сразу открывает чтение/ZIP и закрывает редактирование. Это заменяет прежнее временное ожидание даты первого тура; остальные ограничения сохраняются.
